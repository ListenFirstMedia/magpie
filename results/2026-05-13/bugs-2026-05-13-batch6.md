# Bugs — Batch 6 (run 2026-05-18)

## BC-2 — Brand > Content CSV export filename is a CDN hash, not the spec format

- **Severity:** Medium (data correct; filename misnamed; end-user spreadsheet hygiene affected)
- **Discovered in:** QA-531 (Brand > Content - Facebook - CSV for Unauthorized Brand)
- **Env:** dev (`app.lfmdev.in`)
- **Account/brand:** Adam Orfei / Star Wars (brand_id 75007)
- **Date:** 2026-05-18

### Repro

1. `Brand → Content`, select any brand (Star Wars used here).
2. Set channels to Facebook only and Apply.
3. Click `Export` (top-right) → `Ok` in the "Export Select Data Sets" modal.
4. Wait ~30 sec → notification (bell icon) shows `Select Data Sets Export … is now ready. Download file.`
5. Inspect the anchor's saved filename (programmatically or by clicking and observing the saved file).

### Expected
Saved filename: `Brand-Content-20260511-20260517-posts.csv` (matches QA-531 A2 = `Brand-Content-YYYYMMDD-YYYYMMDD-posts.csv`).

### Actual
Saved filename: `290891-1cf67c943fca0bb956460b27440d6537.csv` (CDN object key).

### Evidence

- Anchor element: `<a href="https://analytics-cdn.lfmdev.in/290891-1cf67c943fca0bb956460b27440d6537.csv" download="">Download file</a>`
  - `download` attribute is empty string → browser does NOT override URL filename.
- Response headers from CDN (captured via in-page fetch):
  ```
  content-length: 16032
  content-type: binary/octet-stream
  etag: "e531d17e006b5e9471d99f0bddb1fa97"
  last-modified: Mon, 18 May 2026 14:47:27 GMT
  ```
  No `Content-Disposition` header → browser does NOT override URL filename.

### Root cause hypotheses

Either:
1. **Server-side miss** — the CDN object should be served with `Content-Disposition: attachment; filename="Brand-Content-20260511-20260517-posts.csv"`. Likely needs S3 (or equivalent) per-object metadata or signed-URL response-content-disposition param.
2. **Client-side miss** — the React notification component renders the anchor without a `download` attribute value; it should set `download="Brand-Content-<from>-<to>-posts.csv"`.

Either fix would satisfy A2; both together would be belt-and-suspenders.

### Impact

End users save raw CDN hashes (`290891-1cf...csv`) and lose the ability to identify exports by brand/date in their Downloads folder. Existing automation that relies on the documented filename pattern (e.g. monitoring scripts at customer sites) will fail.
