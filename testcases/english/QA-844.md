## Description
Verify that post tags applied on TikTok posts via Brand > Content propagate into the exported CSV. (Per closed bug LFMP-30048 the tag column previously was missing.)

## Preconditions
User logged in as Adam Orfei. TikTok-eligible brand (MTV `brand_id=4018`) with at least one TikTok post visible in the chosen date window. One or more tags already applied to TikTok posts (use existing tags rather than mutating).

## Steps
1. Brand → Content, brand = MTV, channel = TikTok only, Default In-Window, recent date window (last 30 days).
2. Verify Posts(N>0) with TikTok rows visible. Note one row with an existing tag (or apply a tag via Bulk Tag if none — MUTATING fallback only).
3. Export → CSV.
4. Wait for queued-export notification → fetch CSV via `analytics-cdn.lfmdev.in` URL with `credentials:'include'`.
5. Inspect saved CSV on disk for the `Tags` column and verify the tagged TikTok row's tag value appears.

## Assertions
- A1 (step 1): TikTok-only filter active; channel ghost shows TikTok enabled only.
- A2 (step 2): Posts(N>0) for TikTok in the chosen window.
- A3 (step 4): CSV downloads with 200 OK + comma-separated payload (defense-in-depth vs TSV regression).
- A4 (step 5): CSV header row includes `Tags` (or equivalent label `Content Tags`).
- A5 (step 5): For the spot-check TikTok row, the `Tags` cell contains the spec tag string (non-empty for tagged rows).
- A6 (step 5): For non-tagged rows, the `Tags` cell is empty (not e.g. literal `null`).
