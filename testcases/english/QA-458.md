## Preconditions
User is logged in as the **Adam Orfei** account (the test user `lfiqa@listenfirstmedia.com` already has access to this account per the run on 2026-05-13).

## Description
This test ensures the TWC Report rates-category data, for a **Relative Dates** range tied to a specific brand keydate, matches between **dev** and **prod**.

## Steps
1. Click **Reporting** in Top Nav.
2. Select **Time Window Comparison**.
3. Select **Relative Dates** (NOT Absolute).
4. Select **Days** interval.
5. Select **3 days before** and **1 day after** (the keydate).
6. In the Add Brand by Name field, add **The Walking Dead** with the **Public Data** perspective.
7. Click the **keydate** control on the brand row.
8. Select **Season 9 Episode 16** keydate.
9. Select **all rate data points** and the **Avg Responses per Post** metric(s).
10. **Uncheck** the **Show Metrics Graphs** option (under Graph Options).
11. **Check** **Show Share** and **Show Change** (under Table Options).
12. Run Report and review.
13. **Repeat** all steps in a new tab on the **prod** environment (the case wording says "stage" but the description and assertion explicitly say "dev and prod" — proceeding with prod per user instruction).

## Expected
Same brand keydate produces identical numeric values for every rate metric and the Avg Responses per Post metric, across dev and prod.

## Assertions
- **A1 (cross-env parity):** For every rate metric column and every row (relative day -3..+1 around the keydate), the numeric value on dev equals the value on prod exactly.
  - type: table (cross-source: dev vs prod)
  - source: built TWC report on each environment
  - normalization: strip thousands separators; parse as number; preserve decimal precision as rendered
- **A2 (Show Share / Show Change columns present):** When Show Share and Show Change are enabled, the rendered table on each environment includes the corresponding columns. Cross-check those values too.
- **A3 (Graph hidden):** With Show Metrics Graphs unchecked, no chart renders above the table.
