## Preconditions
- User should be logged in as **Adam Orfei**.
- Successfully completed **QA-106218** (a Custom Data Set already exists with a known initial metrics order).

## Description
Verify the edit flow for an existing Custom Data Set: reorder a metric via drag, delete a metric, add a metric, save.

## Steps
1. Hover over **Settings** in the top nav.
2. Click **Custom Data Sets** in the dropdown.
3. Click the **Actions** button on the existing Custom Data Set and click **Edit**. *Note the current Metrics order.*
4. Click the **Engagements** metric and drag it to the **3rd position**.
5. Delete the **#7 metric** (Impressions).
6. Click the search box, type **Views** under **Twitter**, and select that metric.
7. Click **Save**.

## Assertions
- **A1 (step 3):** Page header reads exactly `Edit Custom Data Set`.
- **A2 (step 4):** After the drag, Engagements has rank #3 in the metrics list.
- **A3 (step 5):** The deleted #7 metric (Impressions) no longer appears in the Selected Metrics table.
- **A4 (step 6):** Only the Twitter channel icon is displayed under the newly-added "Views" metric.
- **A5 (step 7):** Final metrics order is exactly: `Reactions, Response Rate, Engagements, Comments, Shares, Engagement Rate, Views`.

## Notes
- **Jira flags this case as "Not Recommended" for automation** — primarily because of the drag-and-drop in step 4. The skill will document a fallback strategy (e.g., a Move Up/Move Down API on the row, or programmatic DnD via `dragstart`/`dragover`/`drop` events).
- Hard dependency on QA-106218: cannot run if no Custom Data Set exists for Adam Orfei.
- The assertion expects the deleted #7 metric to be **Impressions** specifically — implying the initial order known from QA-106218 ends with Impressions at position 7.
